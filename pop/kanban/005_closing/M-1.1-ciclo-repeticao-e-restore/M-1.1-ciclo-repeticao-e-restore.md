# M-1.1-ciclo-repeticao-e-restore — Update de fluxo de backups

- **Origem:** [[pop/MODIFICATIONS|M-1]]
- **Plano:** [[M-1.1-ciclo-repeticao-e-restore.plan]] · **Aprovação:** [[M-1.1-ciclo-repeticao-e-restore.approval]] · **Verificação:** [[M-1.1-ciclo-repeticao-e-restore.verify]]

## O quê

Cinco mudanças no fluxo de backup:

1. **`repeat_cicle` no JSON** — valores `15m, 30m, 1h, 3h, 6h, 12h, 24h`; o backup se repete em ciclos dentro do dia usando o horário marcado como referência inicial (ex.: 3:00 AM com `12h` roda 3:00 e 15:00; com `3h` roda 3/6/9/.../0:00 e reinicia às 3:00).
2. **`name` no JSON** — nome personalizado por backup, usado pelos comandos abaixo.
3. **`--force <name>` no script central** — força a execução manual de um backup pelo serviço.
4. **`max_backups` só para `compacted`** — o campo não se aplica aos demais tipos; quando não compacted é ignorado e vale 1 por padrão.
5. **`--restore <name>` no script central** — restaura o backup remoto na pasta atual limpando o conteúdo; se compacted, descompacta o mais recente.
6. **`--validate` no script central** — valida que o JSON tem todos os campos necessários em todos os objetos do array.

## Por quê

Backups diários únicos são esparsos demais para dados que mudam rápido; ciclos intra-dia, nomes identificáveis e operação manual (force/restore) tornam o serviço útil no dia a dia de administração dos servidores.
