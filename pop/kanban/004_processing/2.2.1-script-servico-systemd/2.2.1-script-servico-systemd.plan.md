# Plano — [[2.2.1-script-servico-systemd]]

- **Etapa:** 002_planning · **Responsável:** agent planejador

## Objetivo e resultado esperado

- **Objetivo:** criar `service.sh` para gerenciar o serviço de backup como unit + timer de systemd de usuário.
- **Resultado observável:** `./service.sh install|enable|disable|status|remove` gera os units em `~/.config/systemd/user/` com o intervalo do `.env` e opera o timer via `systemctl --user`.

## Estratégia

Shell script no padrão dos já existentes (`install.sh`, `setup-rclone.sh`): `set -euo pipefail`, funções pequenas, ações por subcomando. Nível **usuário** (`systemctl --user`) — não exige root no servidor remoto; o README (Epoch 3) cobre `loginctl enable-linger` para rodar sem sessão aberta. O timer usa `OnBootSec=2min` + `OnUnitActiveSec=<intervalo>min`, com o intervalo lido de `BACKUP_INTERVAL_MINUTES` no `.env` (default 30, validado como inteiro positivo). `ExecStart` aponta para o binário `dropbox-rclone` na pasta do projeto; `install` avisa se o binário não existir. Para ser testável sem systemd: funções puras de geração/leitura separadas, `main` só roda quando executado (guarda `BASH_SOURCE`), override do diretório de units via `SYSTEMD_USER_DIR` e `DRY_RUN=1` ecoando os `systemctl` em vez de executar.

## Riscos e condições de aborto

- **Risco:** ambiente sem `systemctl --user` funcional — mitigação: `DRY_RUN` e override de diretório permitem gerar/verificar sem systemd; uso real é gate humano.
- **Abortar se:** o formato de timer escolhido for incompatível com o systemd das distros alvo — sinalizar `blocked: true` com evidência.
